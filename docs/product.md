# Продуктовые границы MVP

## Одно предложение

Каждый день пользователь получает 1–5 коротких заданий, чтобы системно готовиться к
Middle Frontend-собеседованию и повторять слабые темы.

## Основная учебная петля

`Уведомление → вопрос → ответ → объяснение → оценка уверенности → следующее повторение`

## Клиенты и порядок выпуска

- Адаптивный React-сайт — первый и основной клиент MVP.
- Telegram — привязка аккаунта, напоминания и короткие single-choice тесты.
- React Native/Expo — второй клиент после проверки сайта; он использует тот же API, DTO и
  алгоритм повторения, но имеет собственный native UI.
- PWA-установка, Service Worker и offline queue не входят в web MVP.

## Шесть экранов

1. Onboarding — темы, уровень, дневной лимит, время и timezone.
2. Сегодня — зафиксированная очередь и прогресс дневной сессии.
3. Задание — вопрос и ввод ответа.
4. Результат — правильность, механизм и контрпример.
5. Статистика — точность, повторы, слабые темы и серия дней.
6. Настройки — темы, расписание, Telegram и пауза уведомлений.

## Метрика пользы

Основная метрика — доля завершённых дневных сессий. Вторая — изменение точности по темам,
которые пользователь повторял минимум дважды.

## Не входит в MVP

- React Native и native push до подтверждения web MVP;
- оплата, социальная сеть и публичные рейтинги;
- сложная геймификация;
- AI-интервьюер и AI-проверка правильных ответов;
- отдельная админка, микросервисы и очередь сообщений.

## Критерий первого среза

Пользователь открывает экран «Сегодня», продолжает сессию, отвечает на вопрос, получает
понятное объяснение и видит обновлённый прогресс без перезагрузки страницы.

Onboarding считается завершённым только после серверного сохранения тем, дневного лимита,
локального времени и timezone. Изменение настроек не перестраивает уже зафиксированную дневную
сессию задним числом.
