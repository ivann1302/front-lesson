# Frontend Mentor

Адаптивный сайт для ежедневной подготовки к Middle Frontend-собеседованиям. Пользователь проходит
короткую учебную сессию, получает объяснение после каждого ответа, а слабые темы
возвращаются в интервальное повторение.

## Первый вертикальный срез

- интерактивный web-экран «Сегодня»;
- реальный сценарий гостя, дневной очереди, ответа и объяснения через API;
- общий `pnpm` monorepo;
- Fastify API с healthcheck, гостевой авторизацией, дневной сессией и приёмом ответов;
- Серверные request ID, безопасные ответы на внутренние ошибки и rate limiting write-endpoints;
- Воспроизводимый Docker Compose deployment с healthchecks, persistent SQLite и smoke-тестом;
- CI для quality-checks, браузерных E2E и сборки каждого Docker-образа;
- пакеты для общих типов и контента.
- Zod-схема семи типов заданий и валидированный каталог из 60 материалов.
- SQLite/Drizzle, восстановление гостя и фиксированная дневная сессия.
- Серверная проверка ответов, идемпотентная запись и расчёт следующего повторения.
- Адаптивный интерфейс всех семи типов заданий с загрузкой, ошибкой и безопасным retry.
- Onboarding и серверные настройки тем, дневного лимита, времени и timezone.
- Реальная статистика точности, активности, повторений, тем и серии завершённых сессий.
- Рабочий каталог «Обучение»: 60 материалов, поиск, фильтры по темам и прогрессу.
- Web-раздел «Теория»: 18 оригинальных глав, поиск, фильтры, примеры кода, источники, серверный
  прогресс чтения, процент завершения, закладки и запуск связанной практики.
- Отдельные practice-сессии из каталога, которые не изменяют стабильную дневную очередь.
- Telegram-бот на grammY с `/start`, `/today`, inline single-choice, `/settings` и `/pause`.
- Валидируемый каталог из шести mock-интервью и 30 открытых вопросов.
- Web-режим mock-интервью на 15/30/45 минут: последовательные вопросы, серверный таймер,
  сохранённые тезисы, скрытый до ответа разбор, самооценка, восстановление после перезагрузки и
  автоматическое повторение слабых тем. История хранит последние завершённые сессии и детальные
  отчёты по ответам, показывает динамику уверенности и частые слабые темы; из отчёта можно сразу
  запустить отдельную тренировку.

Продуктовые границы записаны в [docs/product.md](docs/product.md), визуальная спецификация —
в [docs/design/README.md](docs/design/README.md), правила материалов — в

API и модель данных описаны в [docs/api.md](docs/api.md).

## Запуск

```bash
corepack pnpm@9.15.4 install
corepack pnpm@9.15.4 dev
```

- Сайт: <http://localhost:5173>
- API healthcheck: <http://localhost:3000/health>

Сайт обращается к API через относительный путь `/api`; Vite проксирует его на порт `3000`.
Гостевой токен сохраняется в `localStorage`, а учебный прогресс — только в SQLite.

В разработке Telegram-бот запускается отдельно через polling после заполнения
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_INTERNAL_SECRET`, `API_URL` и `APP_URL`:

```bash
corepack pnpm@9.15.4 dev:bot
```

Для кнопки deep link на сайте также укажите `VITE_TELEGRAM_BOT_USERNAME` без `@`. Без него сайт
всё равно покажет команду `/start КОД`, которую можно отправить боту вручную.

После привязки бот понимает `/today`, `/settings`, `/pause`, `/pause 1d`, `/pause 7d` и
`/pause off`. Те же действия доступны через inline-кнопки.

В production polling запрещён: бот принимает webhook на отдельном HTTP-порту. Укажите
`BOT_MODE=webhook`, публичный HTTPS URL в `TELEGRAM_WEBHOOK_URL` (например,
`https://bot.example.com/telegram/webhook`) и случайный `TELEGRAM_WEBHOOK_SECRET` из букв, цифр,
`_` и `-`. Reverse proxy должен направлять путь webhook на `BOT_HOST:BOT_PORT` (по умолчанию
`0.0.0.0:3001`). Бот сам регистрирует URL и `secret_token` в Telegram при старте; запрос без
совпадающего заголовка отвергается. Healthcheck процесса доступен на `GET /health`.

Для локального polling лучше использовать отдельный тестовый токен: grammY удаляет активный
webhook этого токена перед началом polling.

Планировщик Telegram-напоминаний запускается отдельным процессом с теми же `DATABASE_URL`,
`TELEGRAM_BOT_TOKEN` и `APP_URL`:

```bash
corepack pnpm@9.15.4 dev:scheduler
```

Он выполняет один проход при старте, затем запускается по границе каждой минуты, учитывает IANA
timezone, выбранные дни недели и паузу уведомлений. Уникальная запись в `delivery_log` не даёт
отправить одно напоминание повторно после перезапуска. Сетевые ошибки, Telegram `429` и `5xx`
повторяются до пяти раз с exponential backoff; более длинный `retry_after` Telegram соблюдается.
Постоянная ошибка адресата фиксируется в журнале и отключает его канал уведомлений. Сразу перед
каждой первичной или повторной отправкой scheduler ещё раз проверяет дневную сессию: завершённая
сессия получает в журнале статус `skipped`, и напоминание не уходит.
Если процесс был недоступен в точную минуту расписания, после старта он догоняет напоминание в
течение 60 минут, в том числе через локальную полночь.

## Backup и восстановление

Production-команда создаёт согласованную SQLite-копию, проверяет её целостность и оставляет
последние 14 файлов по умолчанию:

```bash
corepack pnpm@9.15.4 build
corepack pnpm@9.15.4 db:backup
```

Пути задаются через `DATABASE_URL` и `BACKUP_DIR`, количество копий — через `BACKUP_KEEP`.
Пошаговый restore drill и рекомендуемый release order описаны в
[docs/operations.md](docs/operations.md).

## Проверка

```bash
corepack pnpm@9.15.4 check
```

Отдельная проверка базы материалов:

```bash
corepack pnpm@9.15.4 content:validate
```

Обновление reference-only каталога публичных страниц Hack Frontend:

```bash
corepack pnpm@9.15.4 content:sources:sync
```

Команда сохраняет только URL и структуру разделов из официального sitemap; правила атрибуции и
подготовки оригинальных карточек и теоретических глав описаны в
[docs/content.md](docs/content.md).

Создание/обновление локальной SQLite-базы:

```bash
corepack pnpm@9.15.4 db:seed
```

Карта разработки сохранена в `frontend_mentor_app_roadmap.html` и остаётся источником
последовательности работ.
