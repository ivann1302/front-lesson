Решение и архитектура

Не начинай с нескольких клиентов. Подтверди продукт через адаптивный сайт, затем добавь React Native поверх готового API.

web first · native later

Web-сайт — первый клиент

React + TypeScript + Vite, адаптивная вёрстка и серверное сохранение прогресса без PWA-инфраструктуры.

  • React Router
  • TanStack Query
  • responsive + accessible UI

Telegram — уведомления

Надёжная доставка без ранней сложности native push. Часть простых вопросов можно пройти прямо в чате.

  • grammY
  • inline keyboard
  • HTTPS webhook

React Native — этап 2

Добавляй после проверки спроса. API, типы, контент и алгоритм повторения уже будут готовы.

  • Expo
  • shared DTO
  • native push позднее

Не делать в первой версии

  • Три полноценных клиента одновременно.
  • Сложную админку: сначала JSON/TS + seed.
  • Микросервисы, Kafka и отдельную очередь.
  • AI-интервьюера раньше проверенной базы вопросов.
  • Оплату, соцсеть и сложную геймификацию.

Формула качественной карточки

  1. Один проверяемый тезис.
  2. Недвусмысленный вопрос.
  3. Ответ нельзя угадать по формулировке.
  4. Объясняется механизм, а не только результат.
  5. Есть пример или контрпример.
  6. Указаны теги, сложность и связанные темы.

Баланс типов в модуле

  • 25% — термины и flashcards.
  • 30% — single/multiple choice.
  • 25% — вывод кода, ошибка, рефакторинг.
  • 15% — открытые вопросы интервью.
  • 5% — архитектурные кейсы.

Минимальный API

Все write-запросы валидируются. Каждый ответ пользователя получает уникальный clientAnswerId.

МетодEndpointНазначениеКритично
GET/healthAPI и БД.Без секретов.
POST/auth/guestСоздать/восстановить гостя.Rate limit.
POST/auth/telegram-codeОдноразовый linking code.TTL + single use.
GET/study/todayФиксированная дневная сессия.Не отдавать answer заранее.
POST/answersСохранить ответ и вернуть объяснение.Idempotency + transaction.
GET/statsАгрегаты по темам и дням.Не тянуть всю историю.
PATCH/settingsТемы, лимит, время, timezone.IANA timezone.
POST/telegram/webhookTelegram updates.Secret header.

Ответ на сайте

  1. Клиент создаёт UUID.
  2. Отправляет itemId, sessionId и payload.
  3. API в транзакции пишет answer и review state.
  4. Возвращает correctness, explanation, nextDueAt.
  5. Повторный UUID возвращает тот же результат.

Telegram-напоминание

  1. Cron запускает scheduler.
  2. Вычисляется локальное время кандидатов.
  3. Проверяются delivery_log и статус сессии.
  4. Отправляется тема и кнопка «Начать».
  5. Фиксируется success или тип ошибки.

Деплой на SprintHost/VPS

React-сайт отдаётся как статика. API, bot webhook и scheduler могут жить в одном Node-процессе на этапе MVP.

Web

Собрать apps/web/dist; SPA-маршруты перенаправлять на index.html.

API + Bot

Держать процесс под PM2, systemd или встроенным manager хостинга. Нужен graceful shutdown.

SQLite

Хранить вне public-каталога, включить WAL и busy_timeout, делать резервные копии.

Когда переходить на PostgreSQL

Когда нужны несколько инстансов API, появляются write-конфликты, тяжёлая аналитика или управляемая репликация — не просто из-за абстрактного числа пользователей.

Рабочий цикл по карте
  1. Открой первую незакрытую задачу слева.
  2. Скопируй промпт текущего этапа.
  3. Проси менять один слой или use case за раз.
  4. Запусти typecheck, tests и ручной happy path.
  5. Поставь галочку только после проверки.
Правила безопасного вайбкодинга
  • Не принимать миграции и auth-код без ручного чтения.
  • Не вставлять реальные токены в промпты и git.
  • Просить маленькие diff, а не полную регенерацию.
  • Для background job отдельно проверять идемпотентность.
  • Каждая зависимость должна иметь конкретную роль.
Когда добавлять AI
После появления проверенного контента и реальных ответов. Первые подходящие функции: дополнительное объяснение с пометкой, follow-up к интервью-вопросу и оценка по заранее заданному rubric. Правильные ответы и расписание повторения должны оставаться детерминированными.
